# Fig. 4: computation time of Logistic SpINNEr with the three IRLS solvers

Section IV-G of the manuscript. Each IRLS step (`ProxyLogistic.m`) can be solved three ways, chosen by
`SP1_SolveMethod`:

- `'woodbury'`: Algorithm 1 of the manuscript. An n × n Cholesky system built from K = A·Aᵀ; the toolbox default.
- `'svd'`: an n × n system built from the economy SVD of the design matrix.
- `'direct'`: the p(p−1)/2 × p(p−1)/2 system of the direct update.

The scenarios (grid, data seeds, λ, fit settings) are those of an earlier timing study of the SVD and direct
solvers, which is not part of the manuscript.

## Design

- **Grid:** p ∈ {30, 45, 60, 75, 90} (p(p−1)/2 = 435, 990, 1770, 2775, 4005) × n ∈ {50, 100, 150},
  5 repetitions (data sets) per (n, p).
- **Data:** the Fig. 1 model (three blocks, γ = 0.5, β = 1, z-scored symmetric Gaussian matrices), seeded per
  (n, p, repetition). `generate_data.m` is an unchanged copy, so the data sets match the earlier study.
- **What is timed:** one Logistic SpINNEr fit with both penalties (`LogisticSpinner.m`, called directly) at fixed
  λ, `maxIters = 100`, once per solver on the same data. Each fit time includes that solver's setup. The order
  of the solvers rotates between repetitions. The times of the SVD and of K alone are recorded separately.
- **Threads:** every timed fit runs on one computational thread (`singleThreadCalc = 2`, `eigSymmetric = true`);
  with MATLAB's default multithreading, operations on small matrices (roughly 60–200 per side) were erratic and up
  to about 10× slower on the test machine, which made the timings unreliable.
- **λ:** not re-selected. The values chosen by cross-validation in the earlier study are stored in
  `lambdas/lambdas_p*_n*.mat` and reused.
- **Warm-up** fits run first so JIT compilation is not timed.
- **Software:** `../software` (SpINNEr `b4fc36b`). Each run saves the IRLS solver file it used as
  `results/ProxyLogistic_used_<timestamp>.m`.
- **Limitation of the SVD code:** it requires n < p(p−1)/2; the run script checks this.

## Files

| File | Role |
|---|---|
| `config_solver_timing.m` | all settings (grid, seeds, fit options, software and λ paths) |
| `generate_data.m` | data set (n, p, repetition) from the Fig. 1 model |
| `run_solver_timing.m` | timed fits; one result file per (p, n, repetition), restartable |
| `summarize_solver_timing.m` | summary table and agreement checks |
| `plot_solver_timing_paper.m` | Fig. 4 panels |

## How to run

```matlab
cd fig4_solver_timing
run_solver_timing(true);  summarize_solver_timing(true);  plot_solver_timing_paper(true);  % quick check (results_smoke/)
run_solver_timing();                                                                       % full experiment, ~3 h
summarize_solver_timing();
plot_solver_timing_paper();
```

`run_solver_timing` skips every (p, n, repetition) already in `results/`. Keep the machine otherwise idle and
prevent sleep (run MATLAB under `caffeinate -i -s` on macOS). Absolute times depend on the machine.

## Outputs (`results/`)

| File | Contents |
|---|---|
| `config_<timestamp>.mat` | configuration of the run, thread count |
| `ProxyLogistic_used_<timestamp>.m` | the IRLS solver file used by the run |
| `time_p<p>_n<n>_rep<r>.mat` | fit times, setup times, ADMM iterations, IRLS steps, objective values, agreement with Woodbury |
| `run_log.txt` | console log of the run |
| `solver_timing_summary.csv` | per (p, n): median times, geometric-mean speed-ups, time per IRLS step, setup times |
| `solver_timing_paper_a.pdf`, `_b.pdf` | Fig. 4 panels (Algorithm 1 and direct only; SVD is timed but not plotted) |

Only `results/solver_timing_summary.csv` of the manuscript run is included in this repository; the per-fit
files are regenerated by `run_solver_timing()`. Absolute times depend on the machine (the manuscript run used a
MacBook Air with an Apple M4 and MATLAB R2025a).
